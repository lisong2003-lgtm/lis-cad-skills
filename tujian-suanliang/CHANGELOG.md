## 0.3.0 — 2026-09-15

**新增：浇筑区分账（后浇带）＋图纸说明自动摘录。** 报物资计划时能一次给出"先浇区"和"后浇带封闭带"两笔，封闭带标号按说明取高一级。

- `--strip-length-m`：本层后浇带中心线总长（在平面图上量一次）。给了才拆；不给只在缺项清单里提示，不会假装拆过。
- `--strip-width-mm`：带宽。优先级 = 人工参数 → 图面说明原文（"宽度均为800"）→ `rules/口径.json` 默认 800（标推定并进缺项）。
- 拆法：带面积 = 带长×带宽，按本层各板厚档面积占比分摊成体积；封闭带单列一行，先浇区同额扣减，**板量合计不变**（单测守住）。
- 说明摘录：带宽/后浇带类型/封闭用混凝土/保留时间自动摘原文，本层图框内命中优先于全图说明页。
- 断行文字按坐标拼回整句后再检索（说明被拆段、中间夹符号时关键词才搜得到）。
- 明确不做：从图面线段自动复原后浇带。实测双线图 24MB 图候选 2469 条、车库图 249 条，几乎全是梁边线/钢筋桁架，误拆比方差不拆更坏。
- **表格绑定**：墙身表按表头列名（编号/标高/墙厚）对齐取墙厚，且表内标高段必须与本层图名区间一致才取，别层的那一行会被挡下并写明；表内编号不再混进根数。真图实测：某墙柱层原先墙全部进缺项（0 型出量），现在按表头读出五型墙厚并出量，1.22 s。
- **`--member-size`**：柱表是竖排转置表、甚至没有截面列的图（表头只有 编号/标高/纵筋/箍筋 这类），柱截面无法从文字取——照表敲一次 `KZ1=500x900,Q2=250`，写进本图配置，之后每层沿用，每行依据标"人工参数"。试过用图面矩形量柱截面：柱编号文字与柱矩形不在一起（多为引线偏置），该路线作废。
- **两个正确性修复（会改既有数字）**：① 截面正则加数字边界——真图上 `XL4 600x800` 这类"编号+空格+截面"的写法，去掉空格后会被读成 4600x800，一张图命中 131 条，同层梁量虚高约 25%；② 构件号切分加边界——`LB1h=130`（编号与厚度之间没空格）不再把尺寸数字吞进编号，字母间空格仍会并（K Z1→KZ1）。
- **同型多标注不再静默**：一个编号在图上有多种截面/厚度标注时取出现次数最多的，全部候选写进该行的"依据"，并在输出顶部提示需核对。
- **洞口扣减**：图面能算出尺寸的洞口（`JD5 720x300` 这类）按 0.3㎡ 起扣、自动从板面积里减；结构平面图常只画洞不注尺寸（两张真图实测：可算 1 处 / 0 处，另有 2 处只画不注），这部分用 `--openings-m2` 照建施补扣，扣多少、从哪来都写进输出与 xlsx。
- **缓存瘦身**：建完索引自动回收解图明细 JSON（21.7MB 图 64MB→31MB，省 34.7MB），`--keep-detail` 可保留；日志报回收量与缓存合计。
- **口径可追溯**：`rules/口径.json` 版本跟技能走（0.3.0），输出头/xlsx 都印口径版本+SHA 指纹，改了口径一眼可见；起扣面积只保留一处定义。
- **Excel 能用**：计划页顶部加一行摘要（净量/订货/钢筋带/层高/口径），冻结表头、设列宽、方量两位小数；"口径与依据"页收洞口扣减、层高算法、⚠️ 需核对与缺项。
- 真图回归：两张命名体系不同的结构图（地上楼层 + 地下车库）各跑通，板层拆出「先浇区 + 封闭带」两笔且与拆分前合计守恒；查询 0.5–1.0 s，其中一张说明未注带宽、走默认并已标推定。带公司图纸来源的样张数字只留在本机，不入发布包。
- **层高口径修正（会影响柱/墙量）**：层高表里"标高 X 行注的层高"是 X **往上**那一段，之前直接取用等于取错段。现在按"跟着本层顶板一起浇的柱墙段"取——图名自标的标高区间优先（墙柱层图名最常见），其次本层标高减下层标高；两者交叉核对不一致就在输出里报"需核对"。新增 `--story-basis above` 保留旧取法。真图三张墙柱层图各取到不同的柱段高，含表内那行空白的顶层，0.84–1.14 s。
- 表内标高匹配改为"取最接近的一行 + 小容差"（原容差会把相邻两行只差 10mm 的标高混掉）；往下找层高时跳过降板/找坡这类小数差，并按 `rules/口径.json` 的层高校验区间筛，落不进去视为表内混排多套分区标高，报"需核对"且可用 --story-height-mm 定死。
- 修一个自己埋的坑：`--strip-width-mm 1000` 因用「去掉非数字」解析浮点参数被读成 10000mm，改为数字直接取值、说明原文才提数；带宽超出 100~3000mm 视为异常，进缺项不拆。单测 11 → 18 项（合成数据，不含任何项目数值）。

- 楼层范围改为图框并集，图框不可信（跨度 >200 m，多为坐标聚类凑出来的）时改用"图名窗口"（半径＝相邻真图名中位距离×0.6，夹 20–60 m），避免把邻层构件算进来。
- 轴网自动复原改为显式 `--try-auto-grid`：实测两张天正导出图都取不到轴线（自定义实体不解码），默认不假装能自动，失败就说清要补什么参数。
- 线段裁剪到本层范围再判轴线（覆盖率以本层范围为基准），不被跨图框长线干扰；墙线长按墙标注图层取，图层为空时返回 0 而不是退回"全部图层"凑数。
- 计划表加合计行与口径行；缺项且完全没出数时进程返回 4。

## 0.1.0 — 2026-09-15

首个版本：把"报物资计划"这条做成独立技能，解析复用 cad-file-reader，自己只做索引、楼层切分、口径计算与计划单输出。

- 索引层：按图纸 SHA-256 建 `.cadidx/index.sqlite`（stdlib sqlite3 + rtree），一次解图永久复用；实测 21.7MB 图首次 18.4s，之后单层查询 1.4–1.6s。
- 楼层切分：真图名判据＝"图名附近确有构件标注"，不依赖任何图层命名体系，换设计院可用；找不到图名返回 not-found 并列出图上现有图名，不丢数据。
- 出量：柱（截面×层高×根数）、梁（轴线长合计×截面档分摊）、板（轴网包络面积×板厚档分摊）、墙（墙线长×层高×厚，需 --with-geom）；订货量含损耗；钢筋按含筋率区间给吨数带（双轨校验的副轨）。
- 缺项清单：任何缺依据的构件写明缺什么并给原文示例，不用默认值凑数。
- 输出：`-o` 同时给 .md（口径声明）/.csv/.xlsx（计划表 + 明细，openpyxl 缺失时自动只出 CSV/MD）。
- 口径全部写进 `rules/口径.json`（构件算法、起扣 0.3 ㎡、损耗率、标号来源优先级、含筋率区间、定尺长度），可改可核对。
- 单测 8 项（合成数据，不含真实图纸）：真图名判定、轴网包络、板/梁分摊、柱量与标号、缺轴网进缺项、损耗计算。
- 边界如实声明：计划口径毛量 ±5~10%（板分摊口径 ±10~20%），不替代翻样下料、对量、结算。
